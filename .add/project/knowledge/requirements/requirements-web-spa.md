### 1.1 业务角色

- **访问者**：未登录的人，只能进入注册与登录流程。
- **已认证用户**：登录后可浏览文章、管理自己的文章。
- **文章作者**：对本人文章拥有编辑与删除入口（服务端仍是最终判定）。

> 管理员治理页面不在本 IR 范围；管理员仍可通过现有 API/工具行使其职责，见 §6。

## 2. IR-02 · Web 前端（独立 SPA）

> **原始需求**：为现有的内容发布社区后端提供一个浏览器可用的 Web 界面，使普通用户不必依赖命令行或 API 客户端即可完成注册、登录、浏览文章与管理自己的文章。
>
> **价值**：把已交付的后端能力变成可被人直接使用、可被真实用户体验的产品界面；同时保持现有安全合同（同源 Cookie + CSRF）不变。
>
> **主角色**：访问者、已认证用户、文章作者。
>
> **依赖**：IR-01 已交付的注册/登录/文章能力；现有会话与 CSRF 安全合同；同源 HTTPS 部署；登出与会话恢复的服务端能力（见 §7 待澄清）。

### SR-WEB-01 · 身份入口

**需求场景**：访问者可以在浏览器中完成注册与登录，已登录用户可以退出。所有失败都以统一、不泄露账号状态的方式反馈。

**周边依赖**：IR-01 的注册与登录规则（唯一性、密码规则、隐私声明确认、登录失败统一反馈）；隐私声明内容由部署责任方提供。

#### US-WEB-01.1 · 注册

**User Story：** 作为希望加入社区的访问者，我希望在网页上完成注册，以便之后用用户名和密码登录。

1. WHEN 访问者打开注册页 THEN 平台应展示用户名、邮箱、手机号、密码输入项与当前版本的隐私声明。
2. WHEN 访问者未确认隐私声明 THEN 平台应阻止提交，并说明必须先确认。
3. WHEN 注册成功 THEN 平台应明确提示成功并引导至登录页，不得自动把未确认状态的用户当作已登录。
4. WHEN 注册被拒绝（用户名/邮箱/手机号冲突、密码不合规、字段缺失）THEN 平台应展示可理解的原因，且不透露其他账号的详细信息。
5. 平台不得在浏览器持久化保存用户提交的密码。

#### US-WEB-01.2 · 登录

**User Story：** 作为已注册用户，我希望在网页上登录，以便使用社区功能。

1. WHEN 用户提交正确的用户名与密码 THEN 平台应进入已认证状态，并在后续请求中携带服务端会话。
2. WHEN 登录失败 THEN 平台应展示统一失败提示，不区分凭据错误、账号不存在、停用或删除。
3. WHEN 登录成功 THEN 平台应取得本次会话的 CSRF 令牌，并仅保存在页面内存中。
4. 平台不得把会话凭据或 CSRF 令牌写入 `localStorage` / `sessionStorage`。
5. WHEN 已登录用户刷新页面或重新打开标签 THEN 平台应能判定其登录状态，不得因此误判为未登录或要求重复输入密码（判定方式见 §7 Q2）。

#### US-WEB-01.3 · 登出与未登录访问

**User Story：** 作为已登录用户，我希望安全退出；作为访问者，我不应在未登录时看到文章内容。

1. WHEN 已登录用户选择退出 THEN 平台应终止该会话并回到未登录状态；退出后同一浏览器不得再以该会话访问受保护内容。
2. WHEN 未登录用户访问仅登录可见的页面 THEN 平台应引导至登录页，不展示文章内容。
3. WHEN 任一请求返回未认证 THEN 平台应清理内存态并引导重新登录，不得停留在半登录界面。

### SR-WEB-02 · 文章浏览

**需求场景**：已认证用户可以在浏览器中按时间倒序浏览文章列表、翻页并查看文章详情。

**周边依赖**：IR-01 的可见性规则（违规隐藏、停用/删除用户文章隐藏、无归属文章显示"匿名"）；后端分页契约。

#### US-WEB-02.1 · 文章列表

**User Story：** 作为已认证用户，我希望浏览文章列表并翻页，以便发现内容。

1. WHEN 已认证用户打开文章列表 THEN 平台应按创建时间倒序展示可翻页的文章摘要。
2. WHEN 用户翻页 THEN 平台应加载对应页，并保持可返回上一页。
3. WHEN 当前没有可见文章 THEN 平台应展示空状态，而不是错误提示。
4. 平台不得展示当前用户无权查看的文章。

#### US-WEB-02.2 · 文章详情

**User Story：** 作为已认证用户，我希望打开一篇文章查看完整内容。

1. WHEN 用户打开某篇文章 THEN 平台应展示标题、正文、作者与创建时间；无归属文章的作者显示为「匿名」。
2. WHEN 文章不存在或当前不可见 THEN 平台应展示统一的「内容不可用」提示，不泄露其存在性或状态。
3. 平台应展示后端返回的最新内容，不得因本地缓存展示已过期内容。

### SR-WEB-03 · 文章创作与管理

**需求场景**：已登录用户可以在浏览器中创建文章；作者可以编辑、删除自己的文章。

**周边依赖**：IR-01 的文章规则（仅标题与正文、创建即发布、仅作者可改、删除不可恢复、违规内容由管理员处置）。

#### US-WEB-03.1 · 新建文章

**User Story：** 作为已登录用户，我希望在网页上写并发布文章，以便与他人分享内容。

1. WHEN 已登录用户提交非空标题与正文 THEN 平台应创建文章，并在成功后展示该文章详情。
2. WHEN 标题或正文为空 THEN 平台应阻止提交并提示必填。
3. WHEN 创建失败 THEN 平台应保留用户已输入内容并提示失败，不得静默丢弃。
4. 平台不得向未登录用户提供创建入口。

#### US-WEB-03.2 · 编辑自己的文章

**User Story：** 作为文章作者，我希望在网页上修改自己的文章，以便纠正或更新内容。

1. WHEN 作者打开自己文章的编辑页 THEN 平台应预填当前标题与正文。
2. WHEN 非作者没有编辑权限 THEN 平台不得展示编辑入口（服务端判定仍为最终依据）。
3. WHEN 保存成功 THEN 平台应展示更新后的内容。
4. WHEN 保存失败 THEN 平台应保留编辑内容并提示失败原因。

#### US-WEB-03.3 · 删除自己的文章

**User Story：** 作为文章作者，我希望删除自己的文章，以便不再公开该内容。

1. WHEN 作者选择删除 THEN 平台应在执行前要求显式确认，并说明删除不可恢复。
2. WHEN 删除成功 THEN 平台应使该文章在列表与详情中不再对当前用户可见。
3. WHEN 删除失败 THEN 平台应提示失败，且该文章保持原状。

### SR-WEB-04 · 前端运行与安全基线

**需求场景**：前端在与现有安全合同一致的前提下稳定运行，不因引入 SPA 而放宽认证与传输要求。

**周边依赖**：现有 `__Host-` Cookie 前缀、`SameSite=Lax`、CSRF 头合同；HTTPS 证书与域名由部署责任方提供。

#### US-WEB-04.1 · 同源与安全传输

1. 平台应通过 HTTPS 提供前端与 API，二者同源。
2. WHEN 已认证用户执行写操作 THEN 平台应随请求提交该会话的 CSRF 令牌。
3. 平台不得为前端引入跨域调用，也不得放宽 Cookie 的 `SameSite`/`Secure` 策略。

#### US-WEB-04.2 · 错误与可用性

1. WHEN 后端返回业务错误 THEN 平台应展示可理解的中文提示，并保留用户上下文。
2. WHEN 网络失败或服务不可用 THEN 平台应提示失败并提供重试，不得展示伪造的成功状态。
3. 平台应在常见桌面与移动宽度下可用（基础响应式），关键操作可用键盘完成。

## 5. 采用障碍

| 障碍 | 影响 | 建议处置 |
|---|---|---|
| 同源 HTTPS 部署需要新增静态托管与反代配置 | 部署责任与运维成本增加 | 由部署责任方确认域名/证书/反代归属 |
| 缺少登出与会话查询端点 | 登出后服务端会话仍有效；刷新后无法可靠判定登录态 | 见 §7 Q1/Q2 |
| 前端构建链引入 Node 依赖 | 新增依赖与构建步骤 | 锁定版本、纳入项目检查命令（由设计决定） |
| 管理员仍无图形界面 | 治理动作仍依赖 API/工具 | 明确写入范围外，不承诺 |
