## 2. 五段边界叙事

### 2.1 是什么

**内容社区 Web 前端（Content Community Web Frontend，独立单页应用）**：一个与后端分离构建、同源部署的浏览器客户端，把已有的 JSON 业务能力变成普通用户可直接操作的界面。

它是**界面与交互的拥有者**，不是业务事实的拥有者：文章可见性、所有权、违规判定、账号状态全部仍由后端负责。

### 2.2 核心机制

该单元靠四件事工作：

1. **静态产物 + 同源代理**：构建结果是一组静态文件，由反向代理在同一域名下托管，`/api/**` 转发给 Go 服务；前端与 API 同源，因此浏览器按正常规则携带/发送 Cookie。
2. **不引入第二套认证**：登录仍调用现有 `POST /api/v1/sessions`；会话是服务端不透明 Cookie（`__Host-` 前缀、`Secure`、`SameSite=Lax`）；前端不持有、也不持久化会话令牌。
3. **内存中的 CSRF 令牌**：登录响应返回 `csrf_token`，前端仅存于运行时内存，每个写请求带 `X-CSRF-Token`。
4. **登录态探测**：刷新后没有"当前用户"端点，前端用一次受保护只读请求判定登录态（401 → 未登录），而不是依赖本地存储的标记。

### 2.3 端到端流程

1. 访问者打开站点 → 无有效会话 → 被引导至登录页。
2. 提交登录 → `POST /api/v1/sessions` → 服务端下发会话 Cookie，响应体返回 `csrf_token`。
3. 前端把 `csrf_token` 放入内存，进入已认证态，加载文章列表。
4. 浏览：`GET /api/v1/articles`（时间倒序、分页）、`GET /api/v1/articles/{id}`。
5. 写入：`POST /api/v1/articles`、`PUT|DELETE /api/v1/articles/{id}`，均附 CSRF 头；成功后以后端返回结果刷新视图。
6. 登出：调用**新增的登出端点** → 服务端撤销会话 → 前端清内存态并回到登录页。
7. 任一请求返回 401 → 前端清内存态 → 回到登录页并提示会话已失效。

### 2.4 接缝图

```
┌──────────────────────┐          HTTPS（同源）           ┌────────────────────────┐
│ 浏览器                │ ───────────────────────────────▶ │ 反向代理（TLS 终止）    │
│  SPA 静态产物          │ ◀─────────────────────────────── │  /       → 静态文件     │
│  客户端路由 + 内存态    │                                  │  /api/** → 后端服务     │
└──────────────────────┘                                  └───────────┬────────────┘
                                                                       │ 内部 HTTP
                                                           ┌───────────▼────────────┐
                                                           │ Go 服务 han-server      │
                                                           │  现有 16 个业务端点      │
                                                           │  + 新增登出端点（待设计） │
                                                           └───────────┬────────────┘
                                                                       │
                                                           ┌───────────▼────────────┐
                                                           │ PostgreSQL 18           │
                                                           └────────────────────────┘

外部接缝（不直接触达前端逻辑）：
  域名 / TLS 证书 / 反向代理配置  ← 部署责任方
  隐私声明文本及其版本            ← 部署责任方
  SMTP（注册与凭据邮件）          ← 后端，前端不直连
```

图中每个箭头都是**可独立验证的接缝**：静态寻址、`/api` 转发、Cookie 往返、CSRF 头、401 分支、登出后的会话失效。

### 2.5 设计含义

本边界回答的问题是：**在不改动既有认证与授权合同的前提下，如何让浏览器用户可用**。它刻意避免四个坑：

- 为跨域放宽 `SameSite`/CORS（会让安全合同倒退）；
- 把会话或 CSRF 令牌写进 `localStorage`（XSS 后可被直接窃取）；
- 在前端复制可见性与权限判定（会与后端规则漂移）；
- 为前端新增业务端点（唯一例外是已批准的登出）。

## 3. 四栏边界讨论

### 3.1 管什么（对象 / 属性 / 动作）

| 类别 | 内容 |
|---|---|
| **对象** | 页面/视图（注册、登录、文章列表、文章详情、我的文章）；表单输入；会话呈现态（未登录 / 已认证 / 已失效）；错误与加载状态 |
| **属性** | 标题、正文、分页游标与当前页、列表条目摘要、作者显示名（无归属时为「匿名」）、错误提示文本、加载中/空状态、内存中的 CSRF 令牌 |
| **动作** | 注册提交、登录提交、登出、翻页、打开详情、创建文章、编辑自己的文章、删除自己的文章、重试加载 |

**不属于本单元的对象/属性/动作**：文章可见性判定、所有权判定、违规判定、账号状态、会话存储本身——这些由后端拥有，前端只呈现结果。

### 3.2 接入形态

| 形态 | 是否适用 | 说明 |
|---|---|---|
| 浏览器（桌面与移动 Web） | **唯一形态** | 交付物是静态产物，在浏览器内运行 |
| 命令行 / API 客户端 | 形态边界外 | 已存在，后端直接可用，不经本单元 |
| 原生 App / 桌面客户端 | 形态边界外 | 需求范围外，无对应交付 |

### 3.3 消费者

| 消费者 | 使用方式 |
|---|---|
| 访问者 | 注册、登录 |
| 已认证用户 | 浏览列表与详情、翻页 |
| 文章作者 | 创建文章、编辑/删除自己的文章、登出 |

管理员治理不在本单元消费者范围内（仍通过现有 API/工具），见 §4。

### 3.4 接口契约

| 类别 | 形态 | 消费者 | 契约要点 |
|---|---|---|---|
| 认证 | 同源 HTTPS + JSON | 访问者、已认证用户 | `POST /api/v1/sessions` 登录；**新增登出端点**（形状待设计）；会话 Cookie 的名称、`Secure`、`SameSite` 不变 |
| CSRF | 请求头 | 所有写操作 | `X-CSRF-Token` 取自登录响应，仅内存持有 |
| 文章读取 | `GET` JSON | 已认证用户 | 列表（时间倒序、分页）、详情；不可见内容返回统一结果 |
| 文章写入 | `POST/PUT/DELETE` JSON | 文章作者 | 创建、编辑、删除本人文章；服务端返回最终判定 |
| 我的文章 | `GET/POST` JSON | 文章作者 | `GET|POST /api/v1/users/me/articles` 及其子路径 |
| 错误 | JSON 统一结构 | 全部 | 401 → 回登录；403 → 无权限提示；404 → 内容不可用；422 → 字段级提示 |
| 部署 | 静态产物 + 路径转发 | 运行阶段 | 同源、HTTPS、`/api/**` 转发；不得引入跨域 |

> 只写契约级内容；具体 method 组合、字段名、状态码细节在设计阶段核对现有契约后确定。
