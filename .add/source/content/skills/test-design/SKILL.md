# Test Design — 风险驱动测试规划

## 何时启用

- 稳定设计切片已有足够验收/契约依据时，拆 task 前提前规划测试；不要求等待全部设计完成；
- 批次交付前核对覆盖缺口和执行条件；
- 缺陷或事故需要补专项回归计划。

单个开发 task 的测试代码由实现者随代码完成；跨系统真实 E2E 使用 `skill:e2e-verification` 独立闭环。

## 输入契约

- Story、EARS 验收和边界产物；
- 稳定设计切片的范围、修订与确认来源，相关 ADR、状态/数据/接口契约；
- 风险、适用形态、启用 profile；
- 可用环境、数据、依赖和人工责任人；
- 现有测试、原任务/Case/运行证据及已知缺口；当前活动（如有）、测试建议的登记责任与交回位置。

需求、设计或风险变化时只刷新受影响的映射和验证；未变切片复用仍有效依据，不按版本变化一律重做全项目测试计划。

## Step 1：建立验收—风险地图

逐条拆出：用户目标、可观察结果、关键不变量、失败后果和受影响消费者。优先级由影响与发生可能性决定，不由代码行数决定。

禁止根据当前实现行为生成期望；实现与需求冲突时回到需求/设计澄清。

## Step 2：生成场景

至少检查：

- 主成功路径和替代路径；
- 输入边界、空值、重复、乱序和非法状态；
- 外部依赖失败、超时、取消、重试和恢复；
- 并发、幂等、事务和资源生命周期；
- 身份、权限、敏感数据和审计；
- 容量、性能、可观测性和降级；
- 历史数据、版本混跑、迁移和回退。

每个场景写清前置、输入、动作、预期、证据和清理方式。

## Step 3：选择测试层次

| 层次 | 适合证明 |
|---|---|
| 单元/组件 | 局部逻辑、不变量、边界与错误映射 |
| 契约 | 生产者/消费者对公共 schema 和兼容规则的共同理解 |
| 集成 | 真实存储、协议、模块和基础设施边界 |
| E2E | 少量关键用户旅程与跨系统联通 |
| 性能/安全/韧性 | 非功能风险和故障条件 |

优先在最低且足以证明行为的层次测试；E2E 不承担所有组合，但不能用 mock 链路冒充真实联通。

## Step 4：准备数据与环境

- 明确 fixture 来源、隔离命名空间、创建与清理责任；
- 区分自动化可控条件和需要人工/外部协调的条件；
- 敏感数据使用合规替代物，测试证据不得泄露凭据或个人信息；
- 项目 profile 提供具体测试框架与命令，canonical 不预设工具。

## Step 5：形成任务建议和覆盖映射

- 开发 task：必要单元/组件测试与实现一起闭环，不另留“以后补测试”；
- 专项测试 task：跨模块集成、性能、安全或复杂环境准备；
- E2E task：部署后真实旅程，包含人工辅助点和问题闭环；
- 每项任务建议写明上述类型、本任务关闭条件、后续验证关联、精确所有权、依赖、命令/操作、通过证据和停止条件；开发自测不以需求整体 E2E 为通过条件。

这些是任务建议，不由 test-engineer 在本 Skill 新增 task。task-planner 用 `skill:task-decompose` 核已有原任务，实际登记或复用条目，再用 `skill:batch-plan` 组织依赖；task-planner 把原任务引用与安排回填本测试映射，test-engineer 核对场景覆盖是否一致。建议尚未登记、无人承接或关联冲突就明示“未登记/待协调”，不能称已安排；Step 4 只准备数据环境，不写任务账。

覆盖表以“场景 → SR/US → 测试层 → 原任务/case → 实际证据”为准，附设计切片/修订；任务状态只引用原账，不用单一覆盖率百分比替代。尚未执行的计划、执行失败与独立通过分开，环境受阻要有责任和继续条件。

**自然语言方法产品的适用扩展**：仅当被测产品依赖模型读取自然语言方法并据此工作时安排；非自然语言方法产品不强套此组评测，也不能用 ADD 的方法效果评价替代该项目测试。

| 验证面 | 规划的真实证据 |
| --- | --- |
| 触发与排除 | 正向/负向用户请求、合法直入与不适用活动；是否选择正确方法，不因词命中就报通过 |
| 实际读取 | 目标执行者真正取得的完整有效方法/必要资源与修订；文件存在、父会话读过不证明子执行者实读 |
| 行为与边界 | 同一输入下的真实操作/轨迹：步骤、授权、未知、返工/交回与未执行原因；不以关键词断言替代行为证明 |
| 独立产物评价 | 非原作者按事先标准检查真实产物的完整性、可用性、原有能力回归和失败；作者自评不当独立验收 |

需要比较方法效果时固定输入、模型/配置及人辅助预算，保留失败、重试、转模型与人工接管，不只挑成功样本；命令/Host/模型未运行就记未执行，静态合同检查不能代替实际行为或产物评价。

## Step 6：执行前 Gate

- [ ] 每条关键验收至少有一个证据来源；
- [ ] 高风险失败和安全红线有专项场景；
- [ ] 测试数据、环境、外部依赖和人工责任明确；
- [ ] 开发闭环与 E2E 独立闭环分开；
- [ ] profile 命令真实可运行，未使用不存在的默认工具；
- [ ] 期望不可观察的项已回需求/设计澄清；环境/能力暂缺的验证保留受阻范围与责任，不默认为免测。
- [ ] 任务建议已实际登记/复用并回填原任务引用，未登记或待协调项没有冒称已安排。
- [ ] 当前活动的产出/接收责任与确认来源真实；未答不当通过，必要确认不足只暂停依赖范围。

## 输出

返回稳定设计切片/修订、场景清单、分层、覆盖映射、数据/环境计划、任务建议及实际登记引用、执行顺序、人工边界和阻塞项。只在项目已定义的测试设计位置落盘并交回真实当前活动；规划完成不冒称测试已执行或产品已通过。
