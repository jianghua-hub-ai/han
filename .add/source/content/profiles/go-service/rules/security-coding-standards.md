# Go 安全编码加载门禁

## 1. 适用范围

本规则只在准备修改 Go 源码、Go 测试、生成的 Go 文件或生成 Go 文件的模板时加载。修改其他语言、脚本、配置或文档时不加载。

## 2. 编码前动作

1. 将本规则列入当前任务的读取清单。
2. 同时读取 Go Profile 的 `coding-standards.md` 和项目已登记的安全要求、扫描规则与检查命令。
3. 先核对真实调用方、输入输出、错误、状态、资源和持久化行为。扫描提示不等于变更授权。
4. 如果修复会改变 API、数据格式、错误语义、资源所有权、并发、重试或业务时序，先回到设计或变更授权，不在本规则下直接实施。

## 3. 实施与验证

- 优先使用能保持原行为的局部改写；不通过关闭扫描、伪检查、削弱测试或修改样例消除告警。
- 每项修改都说明风险、保持的行为和验证证据。
- 至少验证正常路径和受影响的失败路径；项目定义的安全扫描、构建和测试命令由项目 Profile 或 Manifest 提供，不在本规则中猜测。
- 发现规则与项目真实安全要求冲突时，保留证据并停止扩大范围；由项目负责人决定是否形成单独设计。

本文件只负责“先加载安全约束”的门禁，不复制项目或 Xplay 专属的安全编号清单。具体安全规则由项目知识和已选检查提供。
