# 可观测性通用规范

> **定位**：规定日志、指标、错误和审计的跨语言契约。实现库、SDK、错误码格式及命令由项目 profile 决定。

## 1. 结构化日志

- 生产日志使用项目统一入口和结构化格式；业务代码不直接向标准输出拼接无结构文本。
- 最小字段包括时间、严重级别、服务/模块、事件、关联标识和结果；敏感数据必须脱敏或不记录。
- 同一事件名和字段语义保持稳定，便于搜索、告警和长期分析。
- 错误日志保留根因与必要上下文，但不得重复打印同一错误链造成噪声。

## 2. 错误契约

- 对外错误使用稳定标识与可本地化信息；内部根因和外部呈现分离。
- 错误标识由领域或模块归属，禁止在调用点临时拼造。
- 未知错误有统一兜底，但不得吞掉真实根因；安全相关失败默认不暴露内部细节。

## 3. 指标与告警

- 指标服务于明确决策，至少写清名称、类型、标签、单位、采样点和预期使用者。
- 标签必须低基数；禁止把用户输入、请求 ID 或错误全文作为标签。
- 告警必须有责任人、触发/恢复条件和处置入口，避免只有阈值没有行动。

## 4. 审计

- 身份、权限、配置、发布、数据导出和高风险操作按安全要求留审计记录。
- 审计记录包含主体、动作、对象、结果、时间和关联标识；不可由普通业务接口静默篡改。

## 5. 项目实现层

项目采用时登记统一日志/指标/错误入口、命名空间、错误标识方案、敏感字段策略、检查命令和责任边界。canonical 不指定 SDK、编程语言或错误码位数。
