# 前端实现通用规范

> **范围**：适用于浏览器、桌面客户端和其他交互式前端，不绑定 TypeScript、React、状态库或构建工具。具体实现由项目启用的前端 profile 补充。

## 1. 数据与状态

- 类型或 schema 必须覆盖外部数据边界；不可信输入先校验再进入业务状态。
- 本地交互状态、共享业务状态和服务端状态分开管理，避免多份可写副本。
- 状态修改通过可命名动作发生，禁止组件跨层直接篡改其他模块内部状态。
- 派生数据按需计算或缓存，不反向成为第二真相源。
- 远端调用从项目已选的数据访问入口发起；是否使用 Store Action、服务端缓存或其他方案取项目实际契约，不由通用 Rule 决定。

## 2. 组件与模块边界

- 组件围绕单一用户意图组织；展示、领域行为、远端访问和平台适配保持边界。
- 共享组件只承载跨业务稳定的视觉与交互契约，不嵌入角色名、菜单 ID、形态枚举等业务规则。
- 依赖方向从业务模块指向稳定公共契约；跨模块调用不得绕过公开入口。
- import 或模块加载不得产生不可控副作用；初始化、销毁和资源清理必须显式。

## 3. 异步与错误

- 加载、空数据、失败、重试、取消、超时和权限不足是不同状态，界面必须可区分。
- 不在捕获异常后返回假成功或生产 mock；错误保持根因并给用户可行动反馈。
- 重复提交、乱序响应和页面离开后的回调必须有明确处理策略。

## 4. Mock 与测试隔离

- mock 只存在于测试 fixture、开发适配层或可裁剪的独立模块中。
- 生产组件和状态模块禁止内联假进度、随机业务数据或失败后返回假数据。
- 构建产物必须能证明 mock 未进入生产路径；项目 profile 提供对应检查命令。

## 5. 可访问性、国际化与安全

- 交互可通过键盘完成，焦点、语义、对比度和错误提示可被辅助技术理解。
- 用户可见文本进入项目国际化体系；业务逻辑不依赖翻译后的展示字符串。
- 默认转义不可信内容；敏感信息不进入 URL、日志、客户端持久化或分析事件。
- 后端授权服务是唯一权威；菜单和操作展示消费项目已有授权合同，不写死角色名、菜单 ID 或业务形态代替授权。具体权限字段、固定权限码格式和守护组件由项目定义，不强制某个名字；前端显示允许不等于后端已授权。

## 6. 项目实现层

项目入口引用已选技术的单一依据（已有架构/ADR 或已登记项目 manifest），包括 profile、公共组件入口、状态/数据访问、检查、废弃接口和例外，不另抄一张取值表。canonical 不预设语言、框架、包管理器或微前端方案。
