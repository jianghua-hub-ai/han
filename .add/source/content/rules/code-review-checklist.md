# 代码与设计评审清单

> **定位**：跨语言的风险检查维度。具体静态命令和框架禁令由已启用 profile 补充。

## 1. 评审输入

- [ ] 目标、设计/ADR、精确 diff 范围、验证命令和已知限制齐全。
- [ ] Reviewer 能看到真实工作树、提交和测试证据，不只依赖作者摘要。
- [ ] 结构改动与行为改动已分离；无关格式化和顺手重构已排除。

## 2. 正确性与契约

- [ ] 主路径、边界、异常、并发、取消、重试和幂等与设计一致。
- [ ] 设计评审时从已确认的边界/核心方案追到设计与验收落点，也从每个新增交互、接口和框架分支反查需求授权及旧消费者影响；一处 finding 修复后复核受影响的一致性。
- [ ] 涉及页面时先核用户动作、状态和成功/失败反馈，再核对应 API、权限、错误与审计；没有接口支撑的页面承诺或没有消费者的接口行为已处理。
- [ ] 公共接口、数据格式、事件和持久化兼容性有消费者证据。
- [ ] 资源/事务/状态所有权唯一，失败路径能收敛且不留下半完成状态。

## 3. 安全与隐私

- [ ] 无后门、隐藏接口、硬编码口令、监听或隐私违规。
- [ ] 鉴权与授权在可信边界执行；输入校验、输出转义和 fail-closed 策略正确。
- [ ] 凭据、个人数据和内部细节未进入日志、错误、URL、示例或测试产物。

## 4. 架构与抽象

- [ ] 对象、属性、动作和模块所有权清楚；依赖方向符合批准架构。
- [ ] project-local/profile 差异未渗入 core；没有为一种形态破坏其他消费者。
- [ ] 新抽象有真实变化点和消费者；未引入不必要层次或重复真相源。

## 5. 可观测性与配置

- [ ] 错误保留根因并使用稳定对外标识；日志结构化且不泄露敏感数据。
- [ ] 关联上下文跨边界传播；关键操作有指标、审计或状态证据。
- [ ] 地址、路径、端口、凭据和策略没有硬编码；配置读取与缺失策略清楚。

## 6. 测试与交付

- [ ] 行为改动有针对性测试，缺陷修复有复现和回归证据。
- [ ] 测试覆盖实际风险而非只追行覆盖率；mock 未污染生产路径。
- [ ] 项目 profile 的 format / lint / type-check / build / test 全绿。
- [ ] 开发批次已完成作者自测、Lead 复核、独立 Reviewer 和必要复审；E2E 任务单独闭环。

## 7. 报告要求

- 只报告可操作问题，按严重级别排序，并引用具体文件/行和失败场景。
- 每条 finding 包含：现状、影响、触发条件、建议修复和验证方式。
- 没有发现时明确写出检查范围与剩余未验证风险，不用“看起来没问题”代替证据。
