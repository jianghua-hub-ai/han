# Release Communication — 版本价值传播

## 何时启用

版本或里程碑已完成交付，需要面向客户、产品、销售或内部团队解释“得到什么”时启用。开发中草稿可以提前准备，但未验证能力不得写成已发布事实。

## 输入契约

- 版本/里程碑及目标受众；
- 已完成需求、验证结果和发布范围；
- 可量化数据、界面/操作变化、演示环境；
- 禁止承诺、渠道格式和人签发责任人。

## 流程

### Step 1：建立事实账本

逐项对账需求、设计、任务、测试与发布证据，标记“已交付 / 限制开放 / 未交付 / 无证据”。只有前两类可以进入对外材料。

### Step 2：翻译客户价值

每项能力按“谁 → 原来遇到什么 → 现在如何完成 → 得到什么结果 → 有什么边界”表达。技术架构只用于解释可靠性、效率或扩展性，不单独冒充客户价值。

### Step 3：选择可感知载体

每条亮点至少绑定一项：

- 界面或操作变化；
- 可量化结果；
- 可完整演示的端到端故事。

没有载体的内容降为技术背书或不发布。

### Step 4：生成材料包

- 发布说明：变化、适用对象、使用入口、限制与升级注意事项；
- 亮点：客户问题、核心收益和证据；
- 价值故事：角色、情境、操作、结果；
- 演示脚本：前置条件、步骤、观察点、失败预案；
- 主张证据表：每条对外表述对应交付/验证来源。

### Step 5：人审与签发

产品核对范围和承诺，市场核对表达与渠道，安全/法务按需核对敏感表述。AI 只提供草稿和待确认项，不自行发布。

## 禁止事项

- 不使用“全面、零风险、完全自动”等无法证明的绝对表述。
- 不把计划、设计、实验或隐藏开关描述为已交付。
- 不编造客户名称、节省比例、性能数字或发布日期。
- 不省略会改变购买或使用判断的重要限制。
