## 3. Findings

### [CRITICAL] IA-DES-R01-F001：个人数据收集与外部转移没有隐私告知、同意和法律依据合同

- 位置：`design.md:596-617`、`design.md:1395-1407`、`design.md:1450`
- 违反依据：产品安全红线 10.1.1～10.1.5（A1）；设计模板隐私预分析；manifest 最小必要原则。
- 现状：注册和管理员创建直接收集用户名、邮箱、手机号，SMTP 还向外部系统传输邮箱及临时凭据；设计仅把数据控制者、地区、隐私声明和同意呈现列为“发布资料输入”，没有收集前告知、同意证据、声明版本、撤回/关闭路径或 SMTP 数据转移授权合同。
- 触发：任何注册、管理员创建、密码重置/重发或转移通知。
- 影响：直接命中 A1 隐私红线；无法证明个人数据收集和向 SMTP 处理方转移已获授权，存在法律与信任危机。
- 最小修复：由业务/法务/项目负责人先决定数据控制者、适用地区、处理目的、法律依据及 SMTP 处理方授权；随后在需求/设计中固定收集前告知、显式同意及版本/时间证据、撤回后的账号行为、数据转移条件。该项会改变消费者可见合同，不能由 Reviewer 代拍。
- 验证：隐私评审通过；契约测试覆盖缺少/过期同意版本、撤回路径和 SMTP 未获授权时 fail closed；审计不得保存多余 PII。

### [HIGH] IA-DES-R01-F002：临时凭据过期后可能回退接受旧永久密码

- 位置：`design.md:543-550`、`design.md:688-690`、`design.md:1192-1202`
- 违反依据：`stories.md:284-288`；设计自身“永久密码不得绕过最新临时凭据”的不变量；认证 fail-closed 原则。
- 现状：`CredentialVerifier` 先选“最新有效 TemporaryCredential 或 permanent password”；改密接口也写成可验证“当前永久、bootstrap 或最新临时凭据”。当重置后的临时凭据已过期、不再被视为“有效”时，文字合同允许回退验证旧永久密码，与 §3.4.4 的禁止绕过结论冲突。
- 触发：管理员重置密码成功，用户等待超过 7 天后使用重置前永久密码登录或提交改密。
- 影响：密码重置无法可靠作废旧凭据，攻击者持有旧永久密码时仍可能获得受限会话并继续改密，破坏凭据替换安全边界。
- 最小修复：明确凭据状态机：存在未 consumed/未 superseded 的最新临时凭据时，只能验证该记录；过期必须统一登录失败，绝不回退永久密码。bootstrap 永久凭据作为初始 admin 的显式例外单独建模。改密只接受建立当前受限会话时实际使用的凭据类型。
- 验证：覆盖重置后旧永久密码、临时凭据有效/过期/superseded/consumed、bootstrap 首登及并发重发；所有失败保持统一 `auth.login_failed`。

### [HIGH] IA-DES-R01-F003：备份恢复策略允许复活已撤销会话和旧凭据

- 位置：`design.md:1284-1286`
- 违反依据：requirements r15 的停用/删除立即结束登录；ADR-0005 即时撤销；模板要求明确备份恢复和脏数据处理。
- 现状：设计写明恢复后旧 Session 是否继续有效“由恢复点决定”，仅建议“优先撤销恢复点后的不确定会话”。数据库快照本身无法知道恢复点之后已撤销的会话、已删除账号、密码重置或审计事实。
- 触发：从早于停用、删除、改密或密码重置的备份恢复 PostgreSQL。
- 影响：已撤销 Session、旧密码或旧临时凭据可能重新有效；审计和幂等状态回退，形成权限绕过和重复副作用风险。
- 最小修复：固定 fail-closed 恢复合同，例如恢复后无条件清空/失效全部 Session，失效未完成的临时凭据，标记 processing/uncertain 幂等记录待核，并形成恢复审计/运行手册；若采用全局会话 epoch 等方案，应由架构责任人确认。
- 验证：真实备份恢复演练，证明恢复前已撤销的 Cookie、旧永久密码和旧临时凭据均不可用，审计能识别恢复事件。

### [HIGH] IA-DES-R01-F004：SMTP 敏感传输只写“安全通道”，没有可实施的 TLS fail-closed 合同

- 位置：`design.md:1343-1353`、`design.md:1357-1363`、`design.md:1393`、`design.md:1450`、`design.md:1496`
- 违反依据：产品安全红线 6.1.2；no-hardcode 缺失关键安全配置时 fail closed；ADR-0011 的临时凭据安全交付。
- 现状：SMTP 会携带邮箱和明文临时密码，但未规定必须使用隐式 TLS 或强制 STARTTLS、证书链和主机名校验、禁止明文/降级/`InsecureSkipVerify`、安全配置缺失时的启动行为。当前“部署资料明确”不足以约束实现。
- 触发：SMTP 配置为明文、机会式 STARTTLS 被降级、证书错误被忽略或代理劫持。
- 影响：临时凭据和个人邮箱可在非信任网络泄露，密码重置链路失守。
- 最小修复：固定允许的 SMTP TLS 模式、最低协议、证书/主机名验证、禁止不安全回退、凭据注入和启动校验；目标 SMTP 无法满足时作为方向决策升级，不得静默降级。
- 验证：集成测试覆盖无 TLS、降级、过期/错主机证书和安全配置缺失均失败；成功路径验证不会记录邮件正文或秘密。

### [MEDIUM] IA-DES-R01-F005：零无归属文章场景没有触发专用邮箱清理

- 位置：`design.md:991-1011`、`design.md:1235-1244`
- 违反依据：requirements r15 的专用通知邮箱清理条件；两份 boundary r03 的 S5；ADR-0013 数据最小化。
- 现状：删除流程调用 `OrphanArticles` 后保留 `retained_email`；清理只由后续 article 处置事务调用 `ClearRetainedEmailIfEligible`。若用户删除时没有文章，或其文章此前已永久删除，就不会再有 article 处置事件触发清理。
- 触发：删除一个没有现存文章的用户。
- 影响：专用邮箱和 email Identifier 可无限保留，违反最小必要原则，并持续阻止该邮箱重新参加唯一性校验。
- 最小修复：`OrphanArticles` 返回可核验待处置计数/完成事实；删除事务在结果为零时立即调用清理合同并追加审计。若不在同事务完成，必须有耐久、可重试的确定触发器，不能依赖未来人工操作。
- 验证：覆盖零文章、多个文章、恢复公开、转移含通知快照、永久删除及审计失败回滚。

### [MEDIUM] IA-DES-R01-F006：登录端点缺少明确的 login CSRF / 同源策略

- 位置：`design.md:55-56`、`design.md:527-532`、`design.md:1273-1274`
- 违反依据：安全评审的 CSRF/fail-closed 要求；设计模板要求信任边界和攻击路径可验证。
- 现状：注册和登录因“没有既有会话”免除 CSRF Header。严格 JSON 与 `SameSite=Lax` 能缩小攻击面，但设计没有禁止 credentialed CORS、没有 Origin/`Sec-Fetch-Site` 校验，也没有定义浏览器已有会话时再次登录的处理。
- 触发：部署或后续实现允许跨站 JSON/CORS，攻击站点用攻击者凭据强制受害浏览器登录并覆盖会话。
- 影响：受害者可能在攻击者账号下产生文章或个人数据，形成账号混淆和隐私泄露。
- 最小修复：明确浏览器 API 为 same-origin；默认拒绝跨源凭据请求；登录至少校验可信 Origin/Fetch Metadata，或采用登录前 CSRF token；定义已有会话的轮换与旧会话失效行为。
- 验证：跨站 form、跨站 fetch、恶意 Origin、允许 Origin、已有会话再次登录和 Cookie 轮换测试。

### [MEDIUM] IA-DES-R01-F007：防暴力破解只有“必须限流”，缺少机制合同

- 位置：`design.md:688-710`、`design.md:1295-1297`、`design.md:1367-1374`
- 违反依据：产品安全红线附录“认证模块必须支持口令防暴力破解机制”；设计模板过载控制需给检测点、丢弃位置和响应。
- 现状：阈值保持 TBD 是合理的，但设计连限流键、窗口/退避方式、状态所有者、可信来源地址提取、账号锁定或延迟策略、恢复条件均未定义。
- 触发：攻击者按单账号、多账号或多来源持续尝试密码，或用 Argon2id 请求耗尽资源。
- 影响：实现者无法安全拆分限流 task；可能只做单 IP 内存计数，被代理、多实例、重启或分布式尝试绕过。
- 最小修复：先固定非数值机制：账号摘要与受信来源的组合维度、计数存储和生命周期、退避/锁定行为、统一失败响应、代理信任边界、审计与低基数指标；阈值继续配置化 TBD。
- 验证：单账号多 IP、多账号单 IP、重启、代理伪造、并发和恢复测试；不得通过响应泄露账号存在性。

### [MEDIUM] IA-DES-R01-F008：公共错误注册表没有覆盖设计中已承诺的错误

- 位置：`design.md:495-525`、`design.md:848-859`、`design.md:1295-1297`
- 违反依据：ADR-0014；observability 错误标识“全量覆盖 + 稳定映射”。
- 现状：核心表未登记正文使用的 `identity.initial_admin_protected`；过载章节承诺稳定 429/503，但没有相应 code；§2.3 又要求依赖故障给清晰 503，而表中未知服务端故障只有 500。
- 触发：治理初始 admin、入口限流、数据库/依赖不可用。
- 影响：实现可能临时拼 code、复用不贴切错误或返回不同 HTTP 状态，客户端与契约测试无法稳定处理。
- 最小修复：补齐唯一错误注册表，逐项定义 HTTP、code、公开 message 语义、是否可重试、日志级别与内部 cause 映射；决定初始 admin 保护使用专用 code 还是统一 `auth.forbidden`，不得两者并列。
- 验证：遍历所有 API/失败分支的契约测试，保证每个公开错误只映射到一个稳定组合。

### [MEDIUM] IA-DES-R01-F009：用户治理列表分页 API 仍不足以生成客户端或测试

- 位置：`design.md:59`、`design.md:892-904`
- 违反依据：design-tdd 接口设计需明确请求/响应字段、默认值、错误和兼容；go-service API 默认行为要求稳定。
- 现状：只给出 `cursor`、`limit` 和 Summary/Detail 字段集合，没有列表响应 envelope、`next_cursor`/结束语义、空列表表示、游标版本/过滤绑定、非法或过期游标错误，也未说明字段缺失与 null。
- 触发：客户端读取普通用户或管理员分页列表。
- 影响：服务端、客户端和测试可能各自发明不同协议；后续修改会成为不必要的 v1 兼容变更。
- 最小修复：定义精确 JSON schema，例如 `items`、`next_cursor`、是否还有下一页；固定排序方向、游标包含的键和过滤条件绑定、非法游标错误、limit 默认/上限配置行为及详情字段的 null/省略规则。
- 验证：空列表、单页、多页、同时间戳、并发插入、非法游标和越权过滤契约测试。
