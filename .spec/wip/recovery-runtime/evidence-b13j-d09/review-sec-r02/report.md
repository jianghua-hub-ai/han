## 5. 四项重点核实

### 5.1 `:1278` 的 `waived-for-test-scope` 新口径是否足以阻断下游误读

**判定：足够。**

`:1278` 同时给出（a）语义定义"范围豁免（test scope only）"；（b）四条否定清单（不改 `tasks.md:649` requires 文本 / 不改任何生产 requires / 不使 S4.5·S4.6 变为已实施 / 不构成安全豁免）；（c）作用面的正向限定"只表示……S4.5/S4.6 未实施不单独构成 S4.4 模拟结果的阻断"；（d）**引用义务**"任何下游卡、报告、评审或 E2E 不得把该标签读作「requires 已满足」，引用时必须同时引用本句"。

关键点在于 (d)：它把"标签语义"从可被摘引的孤立词，变成必须连带引用限定句的复合引用。这比我上轮建议的"只标注 test scope"更强，因为它对下游设了引用义务而不是仅描述事实。

残余：r17 原文 `:1216` 仍含旧标签字面量（逐字保留是 Prompt 要求）。该风险由 `:1251`（"下表「r18 新口径」只取代被点名条款"）+ `:1259`（点名取代该条）覆盖，读者按取代表读即可，不构成开放项。

### 5.2 `:1280` 是否真正解决「S4.6 豁免归属 vs ADR-0030 自述适用边界」冲突

**判定：真正解决，且未越权。**

三步结构完整：
1. **自我否权**：`framework.md:922` 继承关系已固定"key 轮换与退役"属 ADR-0019 硬边界；ADR-0030 约束 8（r18 实测 `:1343`）明列"key retirement capability（ADR-0019 另定）"为**不适用场景**。`:1280` 引用这两处，声明"本 ADR 在 key retirement 上没有决策权限"。
2. **依据替换为单一条**：S4.6 的测试范围豁免"只以 ADR-0028 约束 2 为唯一依据"。ADR-0028 约束 2 真实环境层（`:847`）原文含"真实 FileJournal/HMAC/keyring"，且允许"模拟环境、确定性 fixture、建议值或建议环境租约替代"；约束 1（`:844`）把范围覆盖到测试项目全部 active/todo 卡。故以此作为 S4.6 的模拟处理依据，属**授权范围内的引用**，不是 ADR-0030 自行创设豁免。
3. **作用面收窄 + 结论不变**：只解除 S4.4 模拟前置阻塞；不改变 ADR-0019／ADR-0030 关于 key retirement 的任何结论；不构成 key retirement 的任何放宽。

同时 `:1261`／`:1294` 把约束 8 的引用限定为"保留 ADR-0024／0025 原范围"，与 `:1274`（S3.6 不扩大）闭环，未借约束 8 反向扩大模拟范围。

对照 ADR-0028 约束 3（不得伪造 PASS）与约束 7（安全底线不变）：`:1280` 未产出任何 PASS 声明，也未放宽任何判据。

### 5.3 `:1315` 是否显式否定 r16 两路接受向 r17／r18 延续

**判定：显式否定，且同时否定了 r18 自身的接受地位。**

`:1315` 三句：
1. `preflight-record.md:22` 的"r16 字节绑定、再改即失效"规则**继续有效**，不因本轮写作授权废止；
2. r16 的架构 ACCEPT 与安全 PASS WITH CONDITIONS **只绑定 r16 字节，不自动延续**至 r17／r18；r17／r18 各自须重新取得两路独立接受，任何后续接受须对新字节另行登记；
3. "本 r18 未取得两路接受，**不构成任何接受**"。

第 3 句同时满足本轮"是否如实声明 r18 未取得两路接受"的检查项。`:1369` 追溯行亦复述 (11) 条同义内容，两处一致。

### 5.4 `:1323` 对「`preflight-record.md` §9 测试口径登记」的限定

**判定：足以防止被读成满足 ADR-0030 约束 9(b)。**
