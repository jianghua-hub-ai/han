## 2. 必答问题逐条结论

### Q1 r10 约束 2 的「SQL」口径限定是否解决了 R04 指出的问题，是否放宽了禁止 fallback

**结论：解决了 R04 指出的字面冲突；未放宽禁止自动 fallback。**

- R04 的问题：决策 (a) 选定「独立 PostgreSQL 实例」（:951），而约束 2 字面禁止「SQL」作为 anchor（r09 `:1042`），下位解释段不能覆盖约束正文，形成「决策允许、正文禁止」的直接冲突。
- r10 `:1042` 现文：把「SQL」限定为「以业务数据库或通用 SQL 表作为 anchor 的自动 fallback 或隐式来源」，并写明「显式登记、显式配置、固定指向独立故障域实例的 adapter 不属于被禁路径」。
- 未放宽的部分逐项复核：`file`、`内存`、`fake`、`环境探测后自动选择`、`测试替身注册为生产 provider`、`以空 registry 之外的方式隐式构造 adapter` 六项禁令逐字保留。
- 仍需注意的边界（不构成约束 2 的放宽）：该豁免要求「固定指向**独立故障域实例**」，而独立故障域当前未证明（`:953` 只给判据与否证条件，`:954(d)` 明写「未证明并登记前不得宣称独立」）。因此该豁免不会提前打开任何未验证路径；其实证仍归约束 7。

### Q2 ADR-0032 两节点改写后，S4.23 → S4.24b → S4.22 链是否无环、前置语义是否自洽

**结论：主链无环且前置语义自洽；但存在一处残留顺序自指（见 F004）。**

- `:1220`：候选 S4.23 只把 `Exclusive` 作为「已登记但 closed」的端口接入 bundle，不得填实现、不得脱离 closed。
- `:1222`：候选 S4.24b「requires 候选 S4.23」；S4.23 交付且四端口齐备（`Exclusive` 仍可为 closed）即可启动本节点；「bundle 必须先于锁后端接线，不得先接线后补来源」；`Exclusive` 离开 `recoveryClosedPort` 由本节点交付完成。
- `:1224`：候选 S4.22 requires 候选 S4.24b；`:1223` 候选 S4.24a 与锁后端节点相互独立、均早于 S4.22 生产解除。
- 与 ADR-0030 `:979` 三段式（S4.24b 前 closed／S4.23 只接入／S4.24b 后 POSIX 文件锁）**现在一致**，`S4.22→S4.23`、`S4.24b→S4.23` 方向无回边，`:1226` 无环说明逐字未动（我实测 `:1226` 不在差异集合内）。
- 残留：`:1221` 在 S4.23 与 S4.24b 之间单列了一个「本 ADR 解除条件 1–3 的 POSIX 锁后端与 ACL/负向证据」节点，而实现该后端并产出该证据的正是 S4.24b 本身（`tasks.md:3188`／`:3218` 关闭条件 (2)(3)(4)）。按「每个节点只依赖其直接前驱」读，等于要求证据先于产出它的卡，属顺序自指。此项**不是 r04 引入**（`git diff` 实测 `:1221` 未被本轮修改），但 r04 把它留在新链里，需下一次修订处置。

### B13J-D05-R05-F001（HIGH；阻断 9(b) 入口判定与 S4.23 启动；不阻断文本接受）

- 位置：`framework.md:1054`（约束 9(b)）、`:951`（(a)）、`:958`（启动前置 (i)–(v)）；对照 `.spec/wip/recovery-runtime/evidence-b13j-d05/lead-authorization-r09.md` §3 第 5 条。
- 现文要点：9(b) 要求决策修订「给出**具体产品**、凭据来源、独立故障域论证、部署与 ACL 结论」并被架构与安全独立评审接受；(a) 只给「独立 PostgreSQL 实例」这一形态级目标形态并自认「形态级建议值，不是产品选型完成」；`:958` 自认「本四项只让约束 9(b) 的入口有了可评审对象，并未满足该入口」，并把「具体产品——厂商与托管或自建形态」「受支持大版本/EOM」「具名 owner」「目标环境」「见证形态与保证等级」列为仍缺、须由用户/组织作出的 (i)–(v)。
- 问题：架构侧接受该修订文本，只能满足 9(b) 中「被独立评审接受」这一半；`具体产品` 仍是形态级，按 9(b) 字面入口**不满足**。同时 Lead 授权记录 §3 第 5 条写的是「两路均接受，约束 9(b) 的登记入口才告满足」——该流程口径与 9(b) 字面口径冲突，二者不能同时成立而不作说明。
- 依据：`:951`「形态级建议值，不是产品选型完成」；`:958`「并未满足该入口」「当前仍缺…具体产品——厂商与托管或自建形态」；`:1054`「给出具体产品」。
- 可执行改法（三选一，均需明确记录）：(1) 由用户/组织作出 (i)–(v) 并登记，再据以判定入口满足；(2) 由 Lead 取得授权后修订约束 9(b) 正文，把「登记入口」与「启动前置」拆成两级可核条件（登记＝产品形态＋凭据/ACL/故障域论证；启动＝具体厂商/版本/环境），使字面与流程一致；(3) 若维持现文，则任何「9(b) 已满足」的表述都必须同时写明「按 (i)–(v) 未满足」。
- blocking：**是**（阻断「9(b) 入口已满足」的判定与 S4.23 派发/认领/开始改动）；**否**（不阻断把该 ADR 文本作为决策修订接受）。
