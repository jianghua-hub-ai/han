### 4. `:1118`–`:1122` errata 是否引入安全弱化——未引入，但存在 3 项文本可核性缺口

先确认契约缺陷成立：`:952(b)` 要求 pending 唯一键为**非部分**唯一键且终结行以其为复合外键引用目标；单表单 token 列下终结行必然携带同一 token，故与非部分唯一键冲突。证据链可查：`anchor-env-r01\run-03-selftest.log`（6,094 B）存在，`anchor-schema-r02.sql` 记录 `DROP CONSTRAINT anchor_events_pending_uq` 并改建部分唯一索引。

绕过路径矩阵（强制点取自 DDL 证据 `anchor-schema.sql:70`／`:76`／`anchor-schema-r02.sql:14`／`anchor-schema-r03.sql:16`–`:25`）：

| 攻击路径 | 结果 | 强制点 | 判定 |
|---|---|---|---|
| 同 `(ns, rev, token)` 再插 `kind='pending'` | 23505 | 部分唯一索引 `(namespace, revision, pending_token) WHERE kind='pending'` | 阻断。部分化**未**削弱 pending 唯一性：谓词只排除终结行，pending 行仍在索引内 |
| 同 `(ns, rev)` 换 token 再插 pending | 23505 | `anchor_events_event_uq UNIQUE (namespace, revision, kind)` | 阻断（run-07 实测一致） |
| 无 pending 直接写终结行 | 23514 | `anchor_events_terminal_ref` 触发器 | 阻断，无法「跳过 pending」 |
| 终结行引用他 revision／他 namespace 的 pending | 拒绝 | 触发器 `WHERE namespace = NEW.namespace AND revision = NEW.revision AND pending_token = NEW.pending_token AND kind='pending'`，并校验 `journal_id`／`epoch` 保持 | 实现层阻断；但 **ADR 文本 `:1120` 只写「同 revision 同 token」**，未写 namespace 与 journal_id／epoch → ADR-S09-02 |
| committed 后再追加 abandoned | 23505 | `anchor_events_terminal_uq (namespace, revision) WHERE kind IN ('committed','abandoned')` | 阻断，「同一 revision 至多一个终结行」成立 |
| 受限写入角色 UPDATE／DELETE／TRUNCATE／DDL | 42501 | `REVOKE ... FROM han_anchor_writer` | 阻断 |
| **超级用户** `DROP INDEX`／禁用触发器／`session_replication_role=replica` | **不阻断** | 无 | DB 层约束对超级用户不成立；`:1108` 同段登记 anchor 管理员即集群超级用户，但 errata 未登记该残余 → ADR-S09-03 |

## Findings

### ADR-S09-01（次要／文本缺陷·可核性）`framework.md:1118`、`:1122`

- 证据：`:1122` 以 `anchor_events_event_uq` 作为「同 revision 换 token 再插 pending → 23505」的强制点，但该索引名在 ADR 全文仅此一处出现，未给列与谓词；ADR 内可推的唯一定义在 `:952(b)`／`:1029` 的 `UNIQUE(namespace, revision, kind)`，需读者自行拼合。`anchor_events_pending_uq` 亦同时指旧的约束名（run-03）与现行部分唯一索引（r02 起为 `anchor_events_pending_uq_idx`）。
- 影响：第三方仅凭 ADR 无法直接复核「同一 revision 至多一个 pending 行」，只能依赖模拟自测日志；在决策接受级这属可核性缺口，不构成控制削弱（DDL 证据显示实现正确）。
- 最小修订：在 `:1120` 或 `:1122` 写出三个索引的完整定义与现行名字（`event_uq` = `UNIQUE(namespace, revision, kind)`；`pending_uq` = 部分唯一 `(namespace, revision, pending_token) WHERE kind='pending'`；`terminal_uq` = 部分唯一 `(namespace, revision) WHERE kind IN ('committed','abandoned')`），并说明旧约束名到新索引名的对应。

### ADR-S09-02（次要／文本缺陷·契约不完整）`framework.md:1120`

- 证据：`:1120` 称触发器「校验终结行引用同 revision 同 token 的 pending 行」；实际 DDL 还要求同 namespace、`journal_id` 与 `epoch` 保持不变（`anchor-schema-r03.sql:16`–`:25`）。ADR 文本未写这三项，`namespace` 缺失尤其关键，因为 CAS 键域是 `(namespace, revision)`。
- 影响：按 ADR 字面实现可得到「跨 namespace 引用被允许」的较弱版本，且 `journal_id`／`epoch` 绑定不可核。不削弱现行实现，但削弱决策文本的可实施性。
- 最小修订：把触发器条件写全为「同 namespace、同 revision、同 token 的 pending 行，且 `journal_id`／`epoch` 与 pending 行一致，否则拒绝」。

### ADR-S09-03（次要／控制强度·残余未登记）`framework.md:1122` 对照 `:1108`

- 证据：`:1122` 列出「写入角色 UPDATE／DELETE／TRUNCATE／DDL → 42501；管理员改删裁 → 55000」作为数据库层强制证据；同一小节 `:1108` 登记「anchor 管理员仍为集群超级用户，本地 peer 登录可达」。超级用户可 `DROP INDEX`、禁用触发器或以 `session_replication_role=replica` 跳过普通触发器，故上述强制**只对受限写入角色成立**，对 `:1015` 定义的模型内对手（anchor 实例管理员）不成立。
- 影响：存在把「DB 层已保证终结行互斥/不可改写」误读为对超级用户也成立的路径，进而低估域外见证的必要性。`:1106`／`:1122` 已声明模拟自测与非真实故障域，故不构成 BLOCKER。
- 最小修订：在 `:1122` 增一句「以上强制仅约束受限写入角色；超级用户可绕过索引与触发器，该情形不在本自测覆盖内，只能由域外见证与批准记录比对检出」，并在 `:1106` 残余风险清单中点名同一残余。

### ADR-S09-04（次要／文本缺陷·规范并存）`framework.md:952(b)` 对照 `:1118`–`:1120`

- 证据：`:952(b)` 正文仍写 pending 唯一键须为「非部分唯一键 + 触发器（或两张表）」；`:1120` 采用部分唯一索引 + 触发器并自述「**偏离**『非部分唯一键』字面」。`:952(b)` 未加指向 errata 的交叉引用。
- 影响：ADR 内部两处规范并存，读者只读 `:952(b)` 会采用已被证明不可满足的形态（run-03 实测 23505），或反之认为 r14 擅自放宽约束。
- 判级说明：errata 已论证不可满足并保持安全性质等价，故为文本缺陷而非削弱。
- 最小修订：在 `:952(b)` 末尾加「（该形态在单表单 token 列下不可满足，现行登记形态见 `:1118`–`:1120` errata）」；或在下次约束正文修订时合并。
