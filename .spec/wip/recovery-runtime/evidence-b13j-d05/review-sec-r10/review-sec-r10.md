## 4 条遗留逐条判定

### ADR-S09-01（索引名未定义 / 可核性）——**CLOSED**

- `:1130` 起新增「约束命名与 SQLSTATE 对应」表，`:1134`–`:1140` 逐行给出 `anchor_events_kind_chk`、`anchor_events_event_uq`（`UNIQUE(namespace, revision, kind)`）、`anchor_events_pending_uq_idx`（部分唯一 `WHERE kind='pending'`）、`anchor_events_terminal_uq`、`anchor_events_terminal_ref`（含 namespace／revision／token／`journal_id`／`epoch` 条件）、两个 append-only 触发器与受限角色的 `REVOKE`。
- `:1136` 交代旧名映射：旧非部分唯一约束 `anchor_events_pending_uq` 与复合外键 `anchor_events_pending_ref` 已由 r02 删除。
- 可核性结论：第三方现在可仅凭 ADR 推导「同一 revision 至多一个 pending」——`event_uq` 对 `(ns, rev, kind='pending')` 唯一 + `pending_uq_idx` 对同 token 唯一，二者合取即封闭。
- 与 `:985`／`:1029` 一致性：`:1144` 明确 `:985`／`:987`／`:1011`／`:1029` 中「非部分唯一键」写法自 r14 起按部分唯一索引理解，`:1029` 终结行互斥部分唯一索引与其「不可省略」要求逐字不变。核对一致。

### ADR-S09-02（触发器条件不全）——**CLOSED**

`:1120` 已改为「同 namespace、同 revision、同 token 的 pending 行，且 `journal_id` 与 `epoch` 与 pending 行一致」；`:1138` 表行重复同一条件。与 DDL 证据 `anchor-schema-r03.sql:16`–`:25`（`WHERE namespace=NEW.namespace AND revision=NEW.revision AND pending_token=NEW.pending_token AND kind='pending'`，并校验 `journal_id`／`epoch`）逐项一致。

### ADR-S09-03（超级用户残余）——**CLOSED**
