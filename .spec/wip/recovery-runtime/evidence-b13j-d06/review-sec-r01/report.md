## 2. 必答问题逐条结论

### Q1 `B13J-D05-SEC-R06-F005` 是否被持久修复 → **CLOSED（真修复，不是把禁令改写成可用口径）**

判定依据：

- `:1167` 末两句保留双向兜底：「本口径不放宽上段限制：任何卡片在缺少四项可核结论时仍不得启动；生产解除仍须约束 8 全项与人的明确生产批准。」
- 安全侧接受该界线的实质理由：**登记不改变任何信任边界**——不产生工具、不产生批准主体、不产生执行身份、不产生权限矩阵，也不改变生产行为；把「登记」与「启动」分开不引入攻击面。
- S4.24a 侧一致：`tasks.md:3155` 仍 `- [ ]`、`:3166` 硬 requires `identity-auth-D06`、`:3184` 停止条件「ADR-0031 决策修订未被架构与安全独立评审接受即停止」。

保留意见：`:1167` 是解释性条款，效力低于不变量/约束正文；其最后两句是唯一防放宽保障，后续任何修订**不得删改这两句**（记为 F001 的附属要求）。

### Q2 四项结论的安全可核性 → **方向正确，但存在三处实质缺口（F002/F003/F004）**

| 项 | 现文要求 | 安全侧判断 |
|---|---|---|
| `:1115` 批准主体 | 唯一具名角色、不得自批/兼任执行者/供应方、两条独立记录、三方 SHA256 相等、撤销状态 | 结构基本完整；缺**撤销检查时点**（F005）、**记录载体防篡改**（F006）、**复核人 ≠ 签发人**（F003） |
| `:1116` 执行主体 | 独立非交互子进程、≠root、≠批准角色、不共用凭据、无终端、不继承 secret/审批 key/锁/Journal/keyring | 缺**ENV 封闭白名单**（`:1117` 只写「最小 allowlist」，未枚举、未 `env_clear`）→ F004；缺读取侧与特权组/ptrace 约束 → F008 |

| `:1118` 原生耐久回执 | 工具/备份系统原生写入、独立读取路径、绑定 artifact digest + target + source installation、否证 stdout/exit=0/DB 可连接/本次 run 行 | 绑定维度完整，但**未要求回执真实性/不可伪造**（无签名/HMAC/外部审计号/单调序列），也未禁止执行身份或 root 事后重写回执 → F002 |

攻击性复核（针对任务书点名场景）：
- **「root 读同一路径」**：`:1118` 只要求「root 必须经与写入路径不同的独立读取路径读取」，未要求该路径对执行身份**只读**或不可写。root 读同一路径本身不是漏洞（root 本就全权），真正的缺口是**没有任何机制对抗 root/工具链本身伪造**——见 F002。
- **「回执可被本进程重写」**：`:1118` 禁止「由本次进程充当回执」，但**未禁止本次进程事后覆盖回执文件**；写入者是运行在执行身份下的工具，若回执目录对该身份可写，伪造窗口开放。
- **「ENV allowlist 未覆盖 LD_PRELOAD/路径型注入」**：成立。`:1117`/`1128`–`1136` 表格只写「最小 ENV allowlist；零继承业务 secret」，`:1117` 否证条件只写「ENV 含业务 secret 即 closed」。`LD_PRELOAD`/`LD_LIBRARY_PATH`/`LD_AUDIT`/`GLIBC_TUNABLES` 不是「业务 secret」，因此**能绕过该否证条件**，直接使「唯一批准程序」与「原生回执」失效。确切攻击链：控制 root 启动环境的操作者 → 注入 `LD_PRELOAD` → 获批二进制加载非批准代码 → 以真实程序身份写出「原生」回执并通过 `VerifyRestored` → 三方 SHA256 全部相等（文件本身确实是被批准的那个）。此链不要求替换二进制，故 `:1115` 的三方相等拦不住。

## 3. Findings

### F001 — HIGH — 阻断本轮接受（不阻断 r05 作为历史修订存在，但阻断「四项可核」门禁成立）

- 位置：`framework.md:1120` 与 `:1117`、`:1165`、`:1167` 互斥。
- 现文：`:1120`「在 unknown 项补齐并经架构与安全独立评审接受之前，**任何实施/验证卡不得启动**」；`:1167` 重复同一表述。
- 问题：`:1117` 的 unknown 补证主体被写成「**承载实现卡**与独立主机复跑」，`:1116` 的写入「实现阶段的隔离实测」；而 `:1165` 明写「实施/验证卡**用于产出**约束 8 所需的隔离实测、负向验证与原生回执证据」。⇒ **证据只能由实施/验证卡产出，而实施/验证卡在证据产出前不得启动**：自指死锁，四项中的「宿主隔离实测」永远无法合法补齐，S4.24a 的入口条件在文本上不可满足。这不是「更严格」，而是**不可执行的门禁**——会迫使后续以解释性口径绕开，反而削弱约束效力（与 ADR-0030 r02 的 `B13J-PLAN-R02-F001` 同类，当时定级 HIGH）。
- 攻击者能力假设：不涉及攻击者；这是**治理缺陷**，可被「先启动再补证」的违规操作利用，且违规方可用「文本自相矛盾」为自己辩护。
- 可执行改法：仿 ADR-0030 `:958`/`:960` 三级门，把四项拆成三层——
  1. **决策接受层**（本修订）：判定结构、最小字段、否证条件；
  2. **启动前置层**（仅组织侧、无需实施即可取证）：批准角色任命与两条记录、执行身份具名与切换机制、「目标 installation」「回执产品与读取路径」；
  3. **卡退出条件层**（必须由实施/验证卡产出）：POSIX 隔离实测、权限矩阵负向、真实旧备份与回执样本、独立主机复跑。
  并删去 `:1120`/`:1167` 中「任何实施/验证卡不得启动」的全局表述，改为「仅第 2 层未满足时不得启动；第 3 层为卡的退出条件，不是启动前提」。
- 是否阻断：**是**（阻断 r05 通过 + 阻断 S4.24a 启动）。

### F002 — MEDIUM — 阻断生产解除（不阻断本轮）

- 位置：`framework.md:1118`（`### r05 四项结论` 第 4 项）、`:1138`（不变量 6）。
- 现文：回执须由工具/备份系统原生写入、独立路径读取、绑定三项。
- 问题：**未要求真实性/不可伪造性**——无签名、无 HMAC、无外部系统审计号、无单调序列；未禁止执行身份或 root 事后重写/重建回执文件。攻击者能力假设：root 级误操作或被替换的工具链，可在不影响 artifact digest 的前提下伪造「原生回执」，并通过 `VerifyRestored` 只读核对（schema digest 可从 artifact 读得）。这与题设「root 读同一路径」同类，但更严重：不是读取问题，而是**回执本身可被本机伪造**。
- 可执行改法：回执须由**执行身份取不到凭据的外部方**产出或签名（备份服务器/外部系统审计号/HSM 签名），含产生者身份与单调序列号；读取时验签并记审计；把「回执真实性保证」列为约束 8 的可核证据项。若组织侧无法提供，必须在 ADR 中显式声明「信任边界止于 root，回执不抗 root 伪造」并作为残余风险登记，不得以「原生回执」暗示抗伪造。
- 是否阻断：阻断生产解除；不阻断本轮。

### F003 — MEDIUM — 阻断 S4.24a 关闭

- 位置：`framework.md:1115`（批准记录字段）、`:1117`（no-follow 稳定 fd）。
- 问题：(a) 批准记录只绑定「绝对路径与 SHA256、owner/ACL、受控只读挂载来源」，**未绑定 `st_dev`/`st_ino`**，也未要求执行时用已核 fd 直接 exec（`fexecve`/`execveat(AT_EMPTY_PATH)`）；`:1117` 已写「禁止验后按路径重开」，但**未指定机制**，实施者可用「重新 open + O_NOFOLLOW + 再 hash」自证合规，留下校验与 execve 之间的路径替换窗口。(b) `:1115` 批准记录含「复核人与复核时间」，但**未要求复核人 ≠ 签发人**，一人可自签自核。(c)「受控只读挂载」目前是声明而非可核事实（`:1117` 的 unknown 段自认无实测）。
- 攻击者能力假设：对挂载点有写权限的部署侧操作者或同主机 root（非特权用户可以忽略），在 hash 校验后、execve 前替换同路径文件。
- 可执行改法：批准记录增 `st_dev`/`st_ino`；实现固定「fd 校验 → 由该 fd 执行」；S4.24a 负向用例增「校验后按路径替换二进制必拒」；复核人必须独立于签发人并在批准记录中具名。
- 是否阻断：阻断 S4.24a 关闭；不阻断本轮。

### F004 — MEDIUM — 阻断 S4.24a 关闭

- 位置：`framework.md:1116`、`:1117`、`:1128`–`:1136` 矩阵「环境」行。
- 问题：「最小 ENV allowlist」无枚举、无「`env_clear` 后只加封闭白名单」的要求，否证条件只以「含业务 secret」为准；`LD_PRELOAD`/`LD_LIBRARY_PATH`/`LD_AUDIT`/`GLIBC_TUNABLES`/`PYTHONPATH`/`NODE_OPTIONS` 等注入型变量既非 secret 也未被禁，可绕过「无 shell、固定 argv、唯一批准程序」（攻击链见 §2 Q2）。另未要求对 `:1116` 的「不继承」做 `/proc/<pid>/environ` 实测比对。
- 可执行改法：白名单为**批准记录内固定的封闭字面集**（如 `PATH` 固定值、`HOME`、`LANG`、`TZ`），加 denylist 兜底（上述注入变量 + `*_PRELOAD`/`*_OPTIONS`）；实现要求 `env_clear()` 后逐项 set；卡验收含「子进程 environ 与白名单逐字节相等」断言 + 至少一条 `LD_PRELOAD` 注入负向用例。
- 是否阻断：阻断 S4.24a 关闭；不阻断本轮。
