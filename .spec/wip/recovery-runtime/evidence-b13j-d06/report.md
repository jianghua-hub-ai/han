## 4. 四项结论（ADR-0031 `:1111`–`:1120`）

四项均给出「判定结构与最小字段 + 可核判据 + 否证条件 + unknown + 补证主体」；四项都**不是**已完成结论。

- **2. 执行主体**（`:1116`）：结论形态已定——仅由 root 启动的独立非交互子进程以专用执行身份执行，身份须不等于 root、不等于批准角色、不共用凭据、无交互终端、不继承业务 secret/审批 key/部署锁/Journal/keyring/管理入口凭据。**unknown**：身份切换机制（不得经 `su`/`sudo`/shell 包装）、具名主体、ACL 与 GRANT 矩阵；补证主体＝部署方（主机与数据库侧）＋实现阶段隔离实测；本 ADR 不选具体机制。
- **3. 宿主隔离**（`:1117`）：矩阵已定且不放宽——POSIX 为唯一生产候选（首期仍 closed）：固定 argv 无 shell/无附加 argv、独立进程组与会话且完整 join/reap、no-follow 稳定 fd 且前后 fstat 与路径身份一致、最小 ENV allowlist、除目标连接外无网络、任一预检失败在 Begin 前拒绝；Windows 生产 unsupported，任何 Journal/DB/CAS/文件状态变更前返回退出码 2。**unknown**：上述 POSIX 机制无任何实测证据；补证主体＝承载实现卡与独立主机复跑。
- **4. 原生耐久回执**（`:1118`）：结论形态已定——只能由工具或其备份系统原生写入、独立于本次进程可重读的持久记录提供，root 须经与写入路径不同的独立读取路径读取，且须同时绑定 artifact digest、target 与 source installation 并与 `VerifyRestored` 逐项一致。**unknown**：产品级字段名、存储位置、读取命令、真实性保证与真实旧备份样本；补证主体＝部署方与工具/备份供应方。

### 11.6 三级门禁的语义论证与无环性

因果链（单向，无回边）：

1. **决策接受级**（`:1122`）：产出物是本 ADR 修订的决策级要素，前提只有「本修订被架构与安全独立评审接受」；不依赖任何实现产物，故不会因下游未完成而不可达。
2. **卡证据级**（`:1124`）：证据由实施/验证卡在其范围内产出，是该卡的**退出条件**；卡在一级达成后即可派发、认领、开始改动。把「隔离实测/回执样本」写成启动前置会使二级反过来成为一级的前提，形成自指；本修订明确排除。
3. **生产解除级**（`:1126`）：约束 8 全项（含部署方书面任命与两条批准记录原件、真实旧备份演练、人的明确生产批准）→ 才可能解除生产 closed 与「首期不提供」。

因此一 → 二 → 三严格单向；每一级的判定只引用「上一级已完成」与「本级自身证据」，不存在「本级产物是本级前提」的闭包。事实级取证（任命、身份实测、回执样本）在二级或三级产出，**不**出现在一级的前置里，也不再宣称已被补齐（四项 unknown 原样保留）。
