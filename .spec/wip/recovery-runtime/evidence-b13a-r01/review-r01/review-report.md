### [HIGH] RECOVERY-B13A-CR-R01-F002 - Stop cannot cancel the in-flight startup proof or lifecycle port

- Location: internal/recovery/runtime.go:214, :222 and :232, contrasted with :204 and :699.
- Behavior: RunNormal creates generationCtx but passes the original caller ctx to exclusive acquisition, full proof I/O, ReconcileAndStart and activation. Stop cancels only generationCtx. A cooperative Store read already waiting on its supplied context therefore receives no cancellation from Stop; no PhasePermit even exists at that point. The startup lifecycle receives the same uncancelled ctx.
- Trigger: pause ReadAdmissionSnapshot or ReconcileAndStart, call Stop from a separate valid context while the original RunNormal ctx is still live. Revocation and lifecycle stopping begin, but the supplied port context remains live. Stop then waits on normalDone and cannot finish until an unrelated caller deadline/cancel or port completion. An adapter honoring context cancellation has no signal to help join this work.
- Basis/impact: r50 1501/3522-3537 requires runtime generation revocation, cancellation, actual join and shared ownership; core coding error/resource/concurrency contract. This is a cancellation propagation failure, not a demand that Stop return before actual join. Leaving a cooperative proof read/startup unnotified can stall drain and retain deployment ownership despite a requested stop/fault.
- Minimum repair: derive the operation context from the original context and runtime generation/stop lifetime, propagate it through all startup ports and proof/recheck calls, retain original values/deadline, and still wait for actual completion. Do not detach calls or infer join from timeout.
- Evidence: TestReviewerStopCancelsProofPort and TestReviewerStopCancelsStartupPort both FAIL in final normal and race raw; the proof-port assertion explicitly shows that a pure Store read has no alternate PhasePermit cancellation path. The probes manually release their blocked fixture afterward, joining every goroutine.
- Verification: the supplied context must be cancelled when Stop/fault revokes the generation; a context-cooperative blocking port must actually finish and be joined before deployment ownership is released. Keep the already passing cancelled-Stop and late-startup regression cases.

### [HIGH] RECOVERY-B13A-CR-R01-F003 - Stop returns and releases exclusivity before Verify finishes

- Verification: hold Verify at each external proof boundary, initiate Stop/fault, and show the lease and dependent resources remain owned until the operation actually ends. Include new Verify attempts during drain and a Verify-triggered failure to rule out self-deadlock.
